# Model assessment — 2026-10-17

**Scope:** OpenAI model capabilities, reasoning support, lifecycle and relative resource weights, as documented on **2026-10-17 UTC**. Distinguish API contracts from Codex ChatGPT-sign-in product rules: availability and accounting can differ. This is a model comparison, not a record of local configuration or account entitlements.

Capability-profile definitions and the reusable research procedure belong in [model-selection.md](model-selection.md). Configuration choices and their motivation belong in [settings.md](settings.md) and [pi-subagents.md](pi-subagents.md); the documentation map is [CONTEXT.md](CONTEXT.md).

## Findings

- **GPT-6 Luna** fits focused, well-scoped work with materially lower token/credit weights than the larger models [O7, O10].
- **GPT-6.1 Sol** fits complex, revisable technical work. Published debugging results are close to Astra's, but the maintenance case study contains consequential omissions [O4, O10–O12].
- **GPT-6 Astra** has the strongest inspected evidence for demanding, completeness-sensitive analysis; this does not imply every task needs maximum reasoning [O5, O10, O11].
- Model capability and reasoning depth are independent. Published advice includes Luna Low, Sol 6.1 Medium and Astra Extra High for different task shapes; these are recommendations, not calibrated cross-model units [O10].
- Exact cross-model **included-subscription depletion ratios are unknown**. Published credit weights and same-model speed multipliers are available, but answer different questions [O1, O3].

## Model interface and reasoning support

All seven non-retired API model pages inspected publish **1,050,000 context**, **922,000 maximum input**, **128,000 maximum output**, text/image input and text output [O4–O8]. These are provider API declarations, not client-specific budgets.

| Model(s) | Documented API reasoning effort | Documented API default |
| --- | --- | --- |
| Sol 6.1 | `low`, `medium`, `high`, `xhigh`, `max` | `medium` |
| Astra | `low`, `medium`, `high`, `xhigh`, `max` | Not established by the inspected source |
| Sol 6, Luna 6, all three 5.6 | `none`, `low`, `medium`, `high`, `xhigh`, `max` | `medium` |

Sol 6.1 and Astra do not support API `none`/`minimal`. They require Responses for tool calling [O4, O5, O9]. Reasoning tokens occupy context and are output-accounted in the API; visible answer length does not reveal their count or included-quota charge. No fixed high/medium multiplier is documented [O9].

Codex starting advice such as Luna High or Astra Light/Low is product guidance, not an API default. `xhigh` and `max` are distinct. Codex **Ultra** includes subagent orchestration and is not an API reasoning-effort value or a speed tier. API reasoning `mode: pro` is an independent control [O2, O9].

## Included subscription consumption

**Exact cross-model conversion remains unknown.** OpenAI explicitly states credit prices alone do not determine included subscription usage. Context, reasoning, tools, retrieval, caching, model and task complexity all matter [O1].

Published **Plus and Standard Business** estimates for local messages per five hours:

| Model | Official estimated range |
| --- | ---: |
| Astra | 5–45 |
| Sol 6.1 | 15–160 |
| Sol 6 | 15–150 |
| Luna | 350–3,000 |

These suggest a materially lighter allowance expectation for Luna, not fixed message limits or matched-task model multipliers. The page says Pro currently has no five-hour limit; weekly/other limits may still apply. Flexible Enterprise/Edu uses credits; other plans have different rules [O1].

Documented **same-model** speed multipliers:

| Product speed | Included subscription usage / Standard | Purchased-credit usage / Standard |
| --- | ---: | ---: |
| Standard | 1 | 1 |
| Fast, where eligible | 2.5 | 2 |
| Astra/Sol 6.1 Ultrafast, eligible accounts | 8 | 6 |

These are OpenAI product rules, not effort multipliers; eligibility and client exposure differ [O3]. Local/non-GitHub reviews consume general allowance rather than the separate GitHub Codex Code Review category. Work/Codex and local/cloud activity can share allowance [O1].

## Task-specific capabilities

| Evidence | Reported result | Interpretation and limits |
| --- | --- | --- |
| Official selection guidance [O10] | Luna Low for fine-grained edits/extraction; Sol 6.1 Medium for complex technical deliverables expected to be revised; Astra Extra High for demanding exacting analysis. | Author recommendations support differentiated task profiles, not a controlled quality ranking or a requirement for Extra High in every analysis. Astra Low and Luna Extra High advice also separates model from effort. |
| Sol 6.1 system-card debugging evaluation [O12] | Mean rubric scores: Astra **78.05%**, Sol 6.1 **75.52%**, Sol 5.6 **68.32%**, Sol 6 **64.20%**. All solve only a subset of hard researcher-level debugging tasks. | Provider-reported narrow debugging evidence. A matched cross-model effort/tool budget, statistical significance, review recall and research factuality are not established. Historical comparison values can reflect later versions. |
| Official maintenance case study [O11] | One internal repository, >6,000 files / 1M lines; author-validated findings: Astra Ultra **142**, Sol 6.1 Ultra **131**, Sol 6.1 Medium **86**. Astra caught dependency-related feature flags Sol missed. | Useful Sol work and consequential omissions. Includes research subagents/follow-up turns, not pure inference or controlled high-versus-high. No complete ground truth, repetitions/confidence intervals or general review precision/recall published. Economic results are not subscription conversions. |

The “near-Astra” Sol positioning is compatible with missed cases; it is not equality. The GPT-6 guide also warns Astra may ask more clarifications or run overly broad tests on small tasks [O13]. More capability does not guarantee less total work to reach an accepted result.
